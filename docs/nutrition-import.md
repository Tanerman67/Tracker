# My Rhythm Nutrition JSON import, version 1

Use the Nutrition page's **Import JSON** button to preview a file, then confirm. Import is additive. It never replaces daily logs, other app data, or unmentioned meals. Exporting a full My Rhythm backup includes the Nutrition store. When restoring an old full backup without a Nutrition section, the current food diary is retained.

The root is `{"format":"my-rhythm-nutrition-import-v1","entries":[...]}`. See [`../examples/nutrition-demo.json`](../examples/nutrition-demo.json) for two fictional records. Use 1 to 500 entries and a UTF-8 JSON file up to 1 MB.

Each entry has a stable `id` (2 to 100 alphanumeric, underscore or hyphen characters; reuse it for corrections), `date` in local `YYYY-MM-DD` format (not later than today), `meal` (`breakfast`, `lunch`, `dinner`, `snack`, `other`), `name`, `nutrients` object, and optional `portion`, `notes`, `source`, `createdAt`, `updatedAt`. Portion is `{ "amount": 250, "unit": "g" }`; units are `g`, `ml`, `piece` or `serving`. Source is `manual`, `label`, `chatgpt-estimate` or `other`. Timestamps use ISO 8601. Nutrition values describe the **stated portion**, not per 100 g unless the portion is exactly 100 g.

Every nutrient is `{ "value": 12, "unit": "g", "quality": "estimated" }`. Quality is `measured`, `label`, `calculated`, `estimated` or `unknown`. A missing value is omitted or `{ "value": null, "quality": "unknown" }`. An explicit zero is `{"value":0,"unit":"g","quality":"label"}`. Values are finite nonnegative JSON numbers, not numeric strings. Energy uses `kcal` or `kJ` (converted to kcal). Other nutrients accept mass units `g`, `mg`, `µg` or `ug`; they are normalized to canonical units. Unsupported units and unreasonable quantities are rejected. No IU conversion is assumed.

Supported keys: calories, protein, fat, carbs, fiber, sugars, saturatedFat, transFat, omega3, cholesterol; vitaminA, vitaminB1, vitaminB2, vitaminB3, vitaminB5, vitaminB6, vitaminB7, vitaminB9, vitaminB12, vitaminC, vitaminD, vitaminE, vitaminK; calcium, iron, magnesium, potassium, sodium, phosphorus, zinc, selenium, iodine, copper, manganese. For vitaminA use a `basis` of `RAE`, `retinol`, `beta-carotene` or `unspecified`; vitaminB3 uses `NE`, `niacin` or `unspecified`; vitaminB9 uses `DFE`, `folate`, `folic-acid` or `unspecified`; vitaminE uses `alpha-tocopherol`, `total` or `unspecified`. Values on incompatible bases are shown as mixed and never summed. Do not silently reinterpret a label's measurement basis.

Import preview lists all foods and counts dates, additions, conflicts and skips. Same ID and same content is skipped. Different ID with the same food content is skipped as a probable duplicate. If an ID already exists with changed content, the existing record stays unless you explicitly tick **Replace conflicting IDs**. Importing the same file twice is idempotent. Editing an imported item in the app retains its stable ID and original creation timestamp.

## Copyable ChatGPT instruction

> Create a My Rhythm Nutrition JSON file using the format `my-rhythm-nutrition-import-v1` and an `entries` array. Use a stable unique ID for each food, a local date in `YYYY-MM-DD`, meal (`breakfast`, `lunch`, `dinner`, `snack`, `other`), name, optional portion `{amount,unit}`, source and a `nutrients` map. For example, `protein:{"value":12,"unit":"g","quality":"estimated"}`. Give nutrients for the recorded portion. Never invent zero for unknown values. Omit unknown nutrients or use `{"value":null,"quality":"unknown"}`. Use `measured`, `label`, `calculated` or `estimated` for known values. Support kcal/kJ for calories and g/mg/µg for others. Mark estimates and uncertainty in `notes`. Preserve vitamin measurement basis (A RAE, B3 NE, B9 DFE, E alpha-tocopherol) when known; do not convert IU without reliable information. Reuse food IDs in corrected files to let me review updates. Produce valid JSON only. Do not invent foods or exact amounts when a photo or label cannot establish them.
